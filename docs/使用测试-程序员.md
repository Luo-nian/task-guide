## 1. 一个月时间线

| 时间点 | 我做了什么 | 看到什么 | 哪里出问题（依据） |
| --- | --- | --- | --- |
| 第 1 天 | 装手机端 → 进设置看数据落点 → 电脑端点「扫描设备」配对 → 手机弹窗点「允许」 | 手机端写着「同步服务器 地址 10.103.157.105:8899」；电脑端显示「已配对: http://10.103.157.105:8899」「已连接」；配对前手机必须停留在设置页 | 数据归属清楚：**手机 Room 是权威副本，电脑只是缓存**（技术方案 §1）。放心一半。但第一眼就发现配对密钥 `auth_secret` 和任务同库明文存着（`Auth.kt:51`），而 `AndroidManifest` 是 `allowBackup="true"` 且无任何备份规则文件（`AndroidManifest.xml:22`、`res/xml/` 只有 `track_widget_info.xml`）→ **这两条合起来，我的库里所有东西（含密钥）会被 Android 自动备份带到云端**，与「数据不过云」直接冲突 |
| 第 3 天 | 建每日任务 / 习惯，手机打卡，电脑端看是否跟着动 | 两端状态一致；每日型任务跨天后自动回待办 | 折算逻辑只在**读取层**做，不写库、不污染 `updated_at`（`TaskRepository.kt:121-130`、`lib.rs:424-475`）——这是老手写法，好评。但我试着把电脑端设置里的「每日任务刷新时间」从 00:00 改成别的值 → **两边都没有任何变化**（见问题 B2） |
| 第 1 周末 | 第一次想备份：手机端「数据备份 → 导出 JSON 备份」 | Toast 给出路径，落在 `/Android/data/com.taskbar.app/files/backups/taskguide-backup-*.json` | 这个目录在 Android 11+ 用文件管理器**根本进不去**；没有「分享 / 另存为」按钮；**全仓找不到任何导入/恢复实现**（`SettingsScreen.kt:909-922`，grep「导入」零命中）。备份拿不出、也放不回 → 这次备份只是心理安慰 |
| 第 2 周 | 换网络：家里 WiFi ⇄ 手机热点，路由器重启过一次，IP 变了；也试过双方断网各自改 | 电脑端能靠 mDNS 按 deviceId 重新找到新 IP 并改写地址，断连期间各自可写、重连「先拉后推 + 最多 3 轮重试」收敛 | 机制对得上（`lib.rs:1711-1839`、`sync.rs:704-710`）。风险在环境：路由器开 AP 隔离/双频分离时 mDNS 常不通，就只能手抄新 IP。更要命的是——手机端**没有追踪任务时会退出前台态降级成普通后台服务**，没有任何周期自愈，被系统清掉后电脑端就「连不上」，只能再开一次手机 App（`SyncService.kt:104-129`，重启入口仅开机/网络变化/主界面 `TaskBarApp.kt:46`） |
| 第 3 周 | 双端同时改同一条任务（手机改标题、电脑改优先级，那时正断着网）；另外误删过一条 | 重连后一边的改动被静默吞掉，两端都不提示；删掉的任务被对端一次编辑后「复活」 | 冲突是**整条任务 last-write-wins**，字段级不合并（`TaskRepository.kt:757-766`、`sync.rs:277-289`）；而时间戳各用本机时钟、无偏斜校正、无设备号兜底，**时钟偏快的那台会永久赢**；`delete` 变更干脆不带时间戳（`TaskRepository.kt:246-248`，接收侧用自己 `now()` 补，`:804`），所以协议文档 §4 写的「删除传播优先」在实现里无从判定。**
| 第 1 个月末 | 做导出/恢复演练，评估长期托付 | 导出成功、恢复失败；桌面端连备份按钮都没有 | 恢复路径不存在（见上）；桌面端**没有任何备份/导出**（`lib.rs`/`sync.rs`/`app3.js` grep 备份零命中），而技术方案 §5 承诺的「同步成功后自动导出到 桌面/TaskGuide备份/」**未见实现**。提醒这块：源码注释自述 WorkManager 曾把一条 09:00 的提醒压到 15 小时没执行，已改走 AlarmManager（`ReminderScheduler.kt:96-113`），但升级/重复提醒仍在 WorkManager 上（见 B3） |

## 2. 问题清单（按严重度）

### A · 数据错 / 静默丢

| # | 问题 | 依据 | 建议 |
| --- | --- | --- | --- |
| A1 | 双端同时改同一条 = 整条覆盖，改谁丢谁看**设备时钟**；时钟偏快的一端会永久赢，且两端都不提示 | 【已核实】`TaskRepository.kt:757-766`、`sync.rs:277-289` 均只比 `updated_at`；时间戳取本机 `System.currentTimeMillis()`/`now_ms()`（`TaskRepository.kt:65`、`sync.rs`） | 排序键改成 `(updated_at, device_id)`；接收时用服务端 `server_time` 校正偏斜；冲突发生时至少留一条「被覆盖」记录 |
| A2 | 删除不带时间戳 → 「删了又被改回来」/「改了又被删」先后不可判，协议文档与实现不符 | 【已核实】`ChangeOp("delete", …)` 无 data/无 ts（`TaskRepository.kt:246-248`）；接收侧用本机 `now()` 补戳（`:804`） | `delete` 也带上 `updated_at`（软删时间），与 upsert 用同一套比较 |
| A3 | `allowBackup="true"` 且无备份规则 → 任务库、设置、**配对密钥**都会进系统云备份；换机恢复后旧密钥可能一起复活 | 【已核实】`AndroidManifest.xml:22`；`res/xml/` 仅 `track_widget_info.xml`，无 `fullBackupContent`/`dataExtractionRules`；密钥存 settings 表 `auth_secret`（`Auth.kt:51`） | `allowBackup=false`，或加 `dataExtractionRules` 显式排除数据库与 prefs（至少排除密钥） |
| A4 | 只有导出、没有导入；导出文件落在**卸载即被删**的私有目录且无法分享出去 | 【已核实】`SettingsScreen.kt:909-922`（`getExternalFilesDir(null)/backups`）；grep 无任何导入实现 | 补「导入 JSON 并合并」；导出改走 SAF/分享，让文件真正落到我自己的目录 |

## 3. 数据安全 / 可迁移性：能不能托付

**传输与鉴权可以放心。** 局域网不是裸奔：ChaCha20 + 签名、180s 时间窗、nonce 防重放、响应双向验签、密钥只投给发起配对的 IP 且一次性交付（`Auth.kt:308-393`、`ApiRoutes.kt:46-141`）。「不经过它的服务器」这句我信。

**但「数据归你管」不成立。** ① `allowBackup=true` 让它上了云、还捎带密钥（A3）；② 导出拿不出也导不回（A4）；③ 电脑端零备份（A4）；两端密钥明文落盘（`lib.rs:1663-1697`），没过系统密钥库。

**可迁移性不及格，但有一条活路。** 买断码是离线 ECDSA、不绑设备（`License.kt`），换机留码即可重新点亮——加分。任务数据相反，我不敢只留一份：现在得自己拷走电脑端 SQLite 并定期手动导出。

一句话：**信它的架构，不信它的兜底。**

## 4. 会不会买断

**会买。** ¥5~12 换一个无账号、无自建云、局域网加密、离线可用、UUID + 软删除 + 增量同步的工具——作者显然懂数据。只为「不做账户体系」这一条也值。

**但不当主力，只当「手机上的第二清单」。** 主力的门票是两件事：**能恢复、冲突可解释**。现在导入缺失、桌面端零备份、LWW 还受设备时钟摆布——出事我救不回来。挂在电脑角落当挂件提醒副屏可以，唯一副本仍留在自己的系统里。

**转正清单（按优先级）：** 导入/恢复可用 → 桌面端自动备份真落地 → 冲突改 `(时间戳, 设备号)` 且删除带时间戳 → 关掉 `allowBackup`。四条做完，我会认真考虑当主力。
