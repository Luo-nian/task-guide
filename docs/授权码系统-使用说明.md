# 授权码系统 · 使用说明（离线买断）

> 目标：**不花一分钱、不需要服务器**地收钱。
> 原理：你电脑上有一把**私钥**，App 里印着对应的**公钥**。你用私钥签出授权码，App 离线验签解锁。

---

## 一、密钥在哪（⚠️ 这是全项目最要紧的文件）

| 文件 | 位置 | 作用 |
| --- | --- | --- |
| 私钥 | `D:\TaskBar-project\secrets\license-private.pem` | **签发授权码**。丢了 → 已卖出的码全废、且无法再签发 |
| 公钥 | `D:\TaskBar-project\secrets\license-public.b64` | 已**编译进 App**（`License.kt` 里的常量） |

- `secrets/` 在 `src/`（git 仓库）**之外**，**永远不会被提交**。✅
- **你必须自己再备份私钥**一份到别处（U 盘 / 网盘 / 手机）。丢了只能换个签名重发 App，老用户无法更新。

## 二、日常只用两条命令

```bash
NODE="C:/Users/Hasee/.workbuddy/binaries/node/versions/22.22.2-3/node.exe"
cd D:/TaskBar-project/src/tools/license

# 卖出一份 → 签发一个授权码（把码发给买家）
"$NODE" gen-license.mjs issue --to 买家昵称 --order 爱发电订单号

# 买家说"码用不了" → 自己先验一下
"$NODE" gen-license.mjs verify <授权码>
```

输出是一串 **137 字符**左右的码，形如：

```
VEIxfHByb3wyMDI2MDkyMHxURVNULTAwMXxCb3Nz.MEYCIQD3Em439qxTrqhwnmqY...
```

（前段是明文信息 `TB1|pro|20260920|订单号|买家` 的 base64；后段是签名。粘贴、邮件、微信发都不怕换行。）

### 首次部署（已经做过了，留档备查）

```bash
"$NODE" gen-license.mjs keygen     # 生成密钥对（只做一次）
"$NODE" gen-license.mjs pubkey     # 打印公钥 → 贴进 License.kt 的 PUBLIC_KEY_B64
```

## 三、为什么公开源码也不怕被白嫖 ⭐

App 里**只有公钥**。ECDSA 的性质决定了：**知道公钥也无法造出合法签名**。
所以这个方案的安全性**不依赖代码保密** —— 仓库公开、APK 被反编译，都没关系。

唯一要保护的就是那把**私钥文件**。它只在你电脑上。

## 四、客户端代码

`mobile/app/src/main/java/com/taskbar/app/billing/License.kt`

| 方法 | 作用 |
| --- | --- |
| `License.verify(code)` | 纯验签，返回 `Info?`（无效给 `null`，不抛异常） |
| `License.redeem(ctx, code)` | 验签通过才落盘到 `taskguide_prefs` |
| `License.isPro(ctx)` | 是否已买断 |
| `License.trackLimit(ctx)` | 同时追踪上限（免费 `FREE_TRACK_LIMIT`，买断不限） |
| `License.clear(ctx)` | 撤销（换码/退款时用） |

### 验证记录（2026-09-20）

| 用例 | 结果 |
| --- | --- |
| 正版码：Node 签 → Java/JCA 验 | ✅ PASS（P-256，payload 正确解出） |
| 改掉码里一个字符 | ✅ FAIL（拒绝） |
| ⭐ **用另一把私钥签同样内容** | ✅ FAIL（**伪造被拒**，这是防伪的关键） |
| Kotlin 端整体编译 | ✅ BUILD SUCCESSFUL |

> `InteropCheck.java` 里的 API 调用与 `License.kt` **逐行对应**，
> 所以"Java 这里通过"就等于"手机上一定通过"，不用装机即可证明。
