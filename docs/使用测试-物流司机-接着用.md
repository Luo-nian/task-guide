# 使用测试 · 物流司机 · 第二个月（接着用）

> 身份：45 岁城际货车司机，一天在车上 10 小时，千元机、阳光直射、戴手套单手操作。已用满一个月，现第二个月。
> 前提：v5.23.0 刚发，下文每条均**对照源码**（不轻信声明）；需求文档自承"真机验证未做，所有修复待真机验证"。

### 1 第二个月第一印象
打开还是那套米白底，太阳一晒字就发灰；提醒这个月总算"新建当晚能响"了，但月底我要换手机，发现备份导出来却**导不回去**——这才是最吓人的。

### 2 时间线（6 点）
1. **第 2 月第 1 天（面对历史数据）**：上月 30 多条任务堆着，逐条删；详情页删除弹了二次确认，手套误触少多了【已核实 TaskDetailScreen.kt:83】。
2. **第 1 周末（清理）**：批量删完，导出备份想留给新车用，文件落在 `Android/data/.../backups`，文件管理器进不去【已核实 SettingsScreen.kt:970】。
3. **第 2 周（强光/手套/颠簸下用）**：白天米白底深褐字，太阳直晒对比度低，单手易点错；"每周一三五 发车检查"这次只在那几天出现、不天天吵了【已核实 ReminderScheduler.kt:81-118】。
4. **第 3 周（提醒可靠性）**：新建"到点交班"当晚真响了；但设"仅电脑端"的照样在手机响、电脑端又不响【已核实 ReminderScheduler.kt:272 scope 未用于派发】。
5. **第 4 周（回顾 + 买断）**：看积分/徽章还行；授权码不在备份里，换机得重找【已核实 导出仅排除 auth_secret，未含授权码】。
6. **月底（换手机）**：导出的 JSON 全仓**没有任何导入函数**，一个月数据眼看要丢【已核实 无 importJson/importBackup；仅 exportJson:958】。
