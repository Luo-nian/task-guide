# 任务指南 TaskGuide —— 同步协议 v1.0

> 手机端（Ktor 服务器）提供 API，电脑端（Tauri 客户端）消费。
> 端口：默认 **8899**（可在手机设置里改）
> 数据格式：JSON（UTF-8）
> 时间戳：Unix 毫秒（如 `1724851200000`）

---

## 1. 局域网发现

### 方式 1：mDNS（NSD 自动发现）
- 服务名：`_taskguide._tcp.local.`
- 手机启动 Ktor 服务器时注册 NSD 服务
- 电脑端启动时扫描该服务，拿到 IP:PORT 自动连接

### 方式 2：手动输入
- 电脑端设置里可手动输入手机 IP（如 `192.168.43.1`，热点网关 IP）
- 手机端 App 设置页显示当前服务器地址（IP + 端口），方便查看

---

## 2. HTTP API

基础路径：`http://<手机IP>:8899/api`

### 2.1 健康检查
```
GET /api/ping → { "status": "ok", "device": "taskguide-mobile", "version": "1.0.0" }
```

### 2.2 全量同步（首次连接）
```
GET /api/sync/full
→ {
    "tasks":    [ {...Task}, ... ],
    "steps":    [ {...Step}, ... ],
    "habit_logs": [ {...HabitLog}, ... ],
    "server_time": 1724851200000
}
```

### 2.3 增量同步（日常）
```
GET /api/sync/incremental?since=1724850000000
→ {
    "changes": [
        { "op": "upsert", "entity": "task",  "uuid": "...", "data": {...} },
        { "op": "delete", "entity": "step",  "uuid": "..." },
        { "op": "upsert", "entity": "habit", "uuid": "...", "data": {...} }
    ],
    "server_time": 1724851200000
}
```
- `since`：电脑端记录的上次同步时间戳（`sync_meta.last_sync`）
- 服务端返回 `updated_at > since` 的所有实体（含软删除的，op=delete）
- 客户端合并：op=upsert 直接覆盖（比较 updated_at），op=delete 标记本地删除

### 2.4 客户端推送自己的变更（电脑端修改后上报）
```
POST /api/sync/changes
Body: {
    "changes": [
        { "op": "upsert", "entity": "task", "uuid": "...", "data": {...} }
    ],
    "client_time": 1724851200000
}
→ { "status": "ok", "accepted": 1 }
```
- 服务端逐条比较 `updated_at`：客户端更新则写入手机数据库，否则忽略并返回最新数据由客户端下次拉取
- 这是"双端对等操作"的关键：电脑上的增删改都能写回手机

## 3. WebSocket 实时推送

```
WS ws://<手机IP>:8899/ws
```

### 服务端 → 客户端（手机推送变更给电脑）
```json
{ "op": "upsert", "entity": "task", "uuid": "...", "data": {...} }
{ "op": "delete", "entity": "task", "uuid": "..." }
{ "op": "reminder", "data": { "task_uuid": "...", "title": "交作业", "strength": "standard" } }
```

### 客户端 → 服务端（电脑上报本地变更）
```
同 2.4 的 change 格式，走 WebSocket 而非 HTTP
```

### 心跳
- 每 30 秒互相发送 `{"type":"ping"}` / `{"type":"pong"}`
- 连续 3 次无响应 → 判定断连，电脑端进入离线模式

---

## 4. 冲突解决规则（单人使用简化版）

| 场景 | 处理 |
|---|---|
| 双端同时改同一任务 | 比较 `updated_at`，**后者覆盖前者** |
| 双端同时新增任务 | UUID 不同，互不影响，都保留 |
| 一端删除一端修改 | 删除传播（op=delete）优先；若删除后又修改，updated_at 较新者胜 |
| 断连期间两端都改了 | 重连增量同步时按 updated_at 逐条合并 |

> 说明：单人使用、双端操作频率低，后写覆盖足够。不需要向量时钟/OT 等复杂算法。

---

## 5. 提醒语义（电脑端收到 reminder 推送时）

| strength | 电脑端行为 |
|---|---|
| standard | 系统通知（Windows Toast）一次 |
| repeat | 通知后 5 分钟重复，最多 3 次 |
| alarm | 弹窗 + 循环提示音，必须手动确认 |

手机端本地提醒由 WorkManager 负责，与推送无关（离线也能提醒）。
电脑端提醒依赖手机推送（`reminder` 消息），**电脑离线时不提醒**（显示在挂件倒计时里）。
