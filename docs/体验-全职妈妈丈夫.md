# 体验 · 全职妈妈丈夫视角（平行用户 / 34 岁男 / 上班族 / 安卓+公司 Win / 共用家庭任务流 1 个月+）

> 我是「全职妈妈(32 岁)」那位的丈夫。两人共用一份数据：她建、我看，接送孩子两人都要看。限制一致：只看截图和代码，没在自己手机装过；【已核实】=核到代码/截图，【推测】=依据前轮报告或常识；**不编造复现步骤**。

## 1 第一印象（≤3句）

干净、不打广告、不登录，这点比滴答清单舒服。但它是**单人 App 套了个电脑同步**，压根没有"两个人"的概念——我们共用，是撞车，不是协作。提醒响在谁的手机上，这事从一开始就是糊涂的。

## 2 我的 5 个使用场景（场景 → 操作 → 顺不顺 → 卡在哪）

**① 上班前看"今天家里有啥"** 手机开 next任务看老婆建了啥。能看，但全混一锅：没有"她的/我的"标记，"接娃 17:00"我看得见时间却不知是不是派给我，"买菜"没时间我以为不急。【已核实】任务表无 owner 列（lib.rs:888）。

**② 公司顺手加"下班顺路缴费"** 公司 Win 开电脑端加。能加；但我不在家 WiFi，手机不在线 → 改动被丢，回家发现没有。【已核实】sync.rs:469-473（断连期桌面改动永久丢失）、push_change:626-642 失败仅 warn。

**③ 她把"接娃"改到 17:30，我知不知道** 她午睡改的。卡：没有任何"配偶刚改了这条"提示——同步只有设备层、无"人"的活动流，我 17:00 去接扑空。【已核实】sync.rs 全篇无 actor。

**④ 提醒响在谁手机** "接娃"是她建的、服务器在她的手机，提醒只响她那台。我在外办事该我接时我手机不响；选"仅电脑端"也照响她手机（scope 坏）。【已核实】ReminderScheduler.kt:156-172、NotificationHelper.kt:125-134。

**⑤ 周末分工** 想派"买菜给我、拖地给她"。卡：没有指派/负责人字段，全仓无此概念，两人只能口头分，App 里仍是一锅粥。【已核实】grep data 层无 assignee；TaskSyncDto(sync.rs:110-135)无 owner。

## 4 ⭐ 颠覆性建议（≥3）

**颠覆1｜把"家庭任务"当一等公民：加负责人/指派 + 按人视图。** 现在它本质是单人 App，两人共用是撞车。对 PM：家庭是最强付费与转介绍场景，没有指派=没有付费理由；与其继续打磨桌宠，不如先让"夫妻共用"真成立。

**颠覆2｜重做通知模型：从"服务器手机响"改为"按负责人设备响"。** 接送/缴费本该响在干那件事的人手机上，现在响在服务器持有者（老婆）那台，我接孩子全靠记。对 PM：家庭场景里提醒错位=功能彻底失效，比不响更糟。

**颠覆3｜冲突不静默覆盖，改"配偶刚改了这条"活动流 + 冲突横幅。** LWW（sync.rs:760-764）让我的编辑无声消失，比报错更伤信任。对 PM：共享数据必须有"谁动了什么"的可观测性，否则用户迟早发现"我写的没了"。

**颠覆4｜家庭空间 = 共享列表 + 各自私人清单，创建人/最后改人上卡。** 一眼区分"她的/我的/我们的"，消除猜测。

| 损失厌恶 | 失去之痛>得到之乐 | 离线编辑被静默丢、换机全丢→"我的东西会没" | 离线队列+导入闭环 |

## 6 会不会推荐给同事 / 会不会买断

**推荐同事：会，但只推"个人用"，不敢推"夫妻共用"。** 共用会翻车（静默覆盖、提醒响错人），推了同事夫妻吵架得怪我。

**买断：¥5~12 能接受，但等"共享指派+按人提醒"做了再买。** 现在买断买不到家庭价值——它卖的是"不打扰的单人清单"，不是"家庭协作"。
