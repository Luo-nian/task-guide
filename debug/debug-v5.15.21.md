### D-001 · 点侧边栏某分类，列表空但实际有任务 【boss 第二次反馈】

**症状**：点侧边栏「限时任务」→ 中间显示"这一类暂时没有任务"，但右侧详情自动选中了
「整理收件箱」、总览里这一栏也有任务。

**根因（双重不一致）**

1. **前后端归类逻辑不一致**（主因）
   - 前端 `catOf(t)`：`category` 不在白名单（daily/goal/time-limited/once）时，**按 `type` 推断**
     （habit→daily / goal→goal / repeat→time-limited / note|once→once）
   - 后端 `lib.rs:get_tasks_by_category`：`WHERE category=?1` —— **只精确匹配字段，无推断**

   → 自定义分类（「工作」「生活」）的任务：**总览能看到（前端推断），分类页查不到（后端查不到）**。

   **证据**（直查 `taskguide.db`，新旧 SQL 对比）：
   | 分类 | 旧 SQL | 新 SQL |
   | --- | --- | --- |
   | time-limited | 0 | **1**（「整理收件箱」category=工作, type=repeat） |
   | once | 1 | **3** |

2. **前端缓存把空结果/失败永久固化**（次因）
   ```js
   if (catTasks[cat]) return;                    // 空数组是 truthy → 永不重试
   ...catch(() => { catTasks[cat] = []; });      // 失败也缓存 []
   arr = catList || tasks.filter(...)            // [] 是 truthy → 不回退
   ```

**修法**
- 后端 SQL 加 type 推断回退分支，与前端 `catOf` 完全等价
- 前端：只缓存**非空**结果；失败**不**缓存；回退用 `catOf(t)` 而非 `t.category`

**关键词**：分类筛选、点分类没任务、这一类暂时没有任务、总览有任务、侧边栏

### D-002 · 电脑端今日待办「一个任务都看不见」【我引入的回归】

**根因**：为了让标语换行，给**全局** `.vh-hint` 写了 `flex: 0 0 100%`。

但今日待办的 `.vh-hint` 位于 `.lv-body`（`flex-direction: column`）内 ——
**column 方向下 `flex-basis:100%` 指"整列高度"**，这条小字把整个列表高度占满，
把任务全挤出可视区。

**修法**
```css
.vh-hint { display: block; ... }              /* 全局恢复块级 */
.view-head .vh-hint { flex: 0 0 100%; }       /* 只对行方向容器内的换行 */
```

**教训**：`flex-basis:100%` 的语义取决于容器方向。给**通用类**加 flex 属性前，
必须先确认它会出现在哪些方向的容器里。

**关键词**：任务看不见、列表空、待办没任务、白色空白、回归

### D-003 · 侧边栏「追踪中」数量改大了却没生效

**根因**：`.nav-count` 在 `style.css` 里**有两处定义**（284 行 + 2612 行），
**2612 行那处才是最终生效的**（CSS 后者覆盖前者）。只改前面那处 → 看起来"没变化"。

**修法**：两处同步改为 `22x20 / 13px`。

**教训**：改 CSS 某条规则前，先 `grep -n "选择器名"` 确认**有几处定义、哪处生效**。

**关键词**：角标、追踪数量、数字太小、没变化、nav-count

### D-005 · 手机端「次数任务的次数」存不进去

**根因**：`TaskRepository.createTask` 里
`target = if (type == MILESTONE) target.coerceAtLeast(1) else 1` ——
**只有里程碑才保留 `target`**，次数任务（`category == "once"`）的次数被强制成 1。

**修法**：条件加 `|| category == "once"`。

**附带**：手机端 `Task` 的 `target`/`progress` 加 `@SerialName("count"/"done_count")`，
使 JSON 与电脑端**双向对齐**（此前电脑端发来的 `count` 手机端收不到 →
次数信息同步不过来，双端积分不一致）。**无需 DB 迁移**（列名不变）。

**关键词**：次数任务、喝水 8 次、次数丢失、count 不同步
