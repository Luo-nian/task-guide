### B-008 · 夜间主题下主界面部分组件仍是浅色（未解决）

- 现象：切到夜间后，设置弹窗已是深墨底，但主界面（列表卡/任务条/部分统计卡）仍是暖白
- 根因：`style.css` 里有 **107 处硬编码 `rgba(255, 25x, …)`** 和 62 处 `#fff`，没走 CSS 变量，
  所以 `[data-theme="dark"]` 覆盖变量后它们不跟着变
- 已试：给 input/select/modal/small-btn/chk-pill/seg-btn/cat-btn/ddl-btn/overlay 加了深色覆盖（这批已好）
- 下一步：把主容器类（列表卡、任务条、统计卡、标题栏）的硬编码暖白逐个换成变量，或统一加一层深色覆盖
- 关键词：夜间 主题 深色 白底 没跟色 硬编码 rgba(255

### B-009 · 桌面端 rust 等级表与前端不一致（只有 5 级，阈值是旧的）—— 未解决

- 现象：**窗口标题栏**显示的等级，在积分超过 200 之后会**永远停在「Lv.5 传奇勇者」**，
  与界面里显示的等级对不上（例如 1555 分，界面是 Lv.8 星辰霸主，标题栏还是 Lv.5）。
- 位置：`desktop/src/lib.rs` → `fn level_of(points)` 里的 `const TABLE`（第 212~228 行）
- 根因：该表**只有 5 级**，下限写的是旧曲线 `0/20/60/120/200`；
  而前端 `desktop/ui/app3.js` 的 LEVELS 是 **10 级**、`0/50/130/250/420/660/1000/1500/2200/3200`。
  ⚠️ 讽刺的是，该函数正上方注释明确写着「等级表必须与前端 app.js 的 LEVELS 保持一致，否则真客户端与预览会显示不同等级」。
  显然是后来把 10 级曲线改了、漏同步这里。
- 调用点：`desktop/src/lib.rs:551`（`let mut lv = level_of(points);` → 窗口标题）
- 影响：仅标题栏文案，不影响积分与升级逻辑（升级用的是前端 LEVELS）；但会让人误以为等级算错。
- 下一步：随「R38 等级名单一数据源」一起修（把 rust 侧改成读前端同一份表，或直接删表改为前端回传）。
- 关键词：标题栏 等级 不一致 只到5级 传奇勇者 level_of TABLE
