## C-007 ⭐ adb 副机连接反复掉线 —— 已解决（环境类，非程序 bug）

**症状**：无线调试一直开着，但 `adb devices` 永远空；`adb pair` 报 `protocol fault`；换新配对码也没用。

**根因有两层**：
1. **adb server 被工具沙箱回收** ⭐：每条命令开头都打印 `daemon not running; starting now` —— 说明 server 进程活不到下一条命令，连接刚建立就被回收。这是"怎么都连不上"的真凶，与手机无关。
2. **Android 无线调试端口漂移**：boss 给的 `30941` 是**配对弹窗端口**，弹窗一关就失效（TCP 直接 RST）；真实连接端口每次开关无线调试都会变。

**排除过程（关键证据）**：
- `ping 10.112.227.105` 通（76ms）+ `tracert` **1 跳直达** → 同网段，不是网络隔离
- `curl http://10.112.227.105:30941` → 目标计算机积极拒绝 → 端口无监听
- `adb mdns services` → **空**（Windows 侧 mDNS 发现不可用）
- 异步端口扫描 30000-50000（28s）→ 命中 **38701 / 39341** 两个开放端口

**修复**：
1. **WMI 拉起常驻 server**：`wmic process call create "adb.exe start-server"`
   - 父进程是 `WmiPrvSE`（持久），server 脱离沙箱存活
   - ⚠️ 陷阱：**WMI 创建的进程不继承 shell 环境变量** → 它监听的是**默认 5037**，不是我们原来设的 5038。所以之后所有 adb 调用都要用默认端口，否则客户端会再拉起一个新 server（又是短命的）。
2. **端口扫描兜底**：`.tmp-data/adb_portscan.py`（asyncio 并发 900，扫 20000 端口 28s）
3. **固化端口**：`adb -s <dev> tcpip 5555` → 之后固定连 `10.112.227.105:5555`（手机重启后失效，需重连一次）
4. **一键脚本** `task-guide/tools/adb-connect.sh`：已有设备 → 5555/5556 → mDNS → 端口扫描，四级兜底

**验证**：跨命令连跑 3 次 `shell echo` + `getprop` 全通（Android 12）；`adb.exe` 常驻仅 1 个进程。

**教训**：
- **配对是一次性的**（凭据存 `~/.android/adbkey`），配对成功后不该再要配对码；端口被拒 ≠ 配对失效
- 排查 adb 掉线，**先看有没有 `daemon not running`** —— 有的话问题在 server 不在手机
- `wmic process call create` 不继承环境变量，跨沙箱启动常驻进程时要留意端口/配置漂移

## C-008 ⭐ streak 有三份实现且规则不同 —— 已解决

**症状**：同一个习惯在「主页 / 所有任务页 / 我的页」显示的连续天数可能不一致。

**根因**：仓库里 `observeHabitStreak` / `observeAllHabitStreaks` / `habitStreak` **三份各自实现**；
v5.15.23 只修了其中 1 份（`observeHabitStreak` 改成"锚点=今天或昨天"），
另外两份仍是老算法（强制从今天起算 → 今天没打卡就是 0）。

**修复**：抽出**唯一**的 `private fun streakOf(dateStrs, today)`，三处全部改为调用它；
规则写死在注释里（今天没打卡 ≠ 断链；昨天断才算断；跨日以本地 0 点为界）。

**验证**：用真实 75 条打卡数据跑算法自检 ——
- 连续 10 天 → 100%（强度）/ streak 10
- 昨天打过、今天没打 → **streak 7（不算断）** ✓
- 连续 3 天后断 5 天 → 强度 17%（缓降不归零）✓

> 呼应铁律：**同一业务逻辑存在多份实现时，修 bug 必须全部找出来一起改**，否则会出现"改了但还是不对"的诡异现象。

## C-009 日历把今天已打卡的习惯标成"未完成" —— 已解决

**症状**：所有任务页 → 日历 → 当日清单里，今天刚打过卡的习惯（列表页明明是绿勾）显示 **"未完成 每日任务"**。

**根因**：日历的完成判断写成 `t.trackStatus == DONE`，但**习惯打卡只写 habit_logs、不改 trackStatus**（仍是 `pending`）→ 永远判成未完成。
连带后果：新增的"整日清空 → 日期数字转玉青"也永远不亮（`allDone` 恒为 false）。

**修复**：给 `TaskCalendarView` 增加 `doneOf: (Task) -> Boolean` 参数，
调用方把"今日已打卡"一并算进来，与列表页统一走 `todayCheckedHabits`：
```kotlin
doneOf = { t -> t.trackStatus == DONE || (t.type == HABIT && t.uuid in todayCheckedHabits) }
```
历史页传 `doneOf = { it.done == 1 }`（逾期未完成不算）。

> **同一状态的判定逻辑散落在多处**是这类 bug 的温床 —— 列表页用 `todayCheckedHabits`、
> 日历用 `trackStatus`，两套标准必然打架。后续再改状态判定时优先抽公共函数。

## C-011 日历"玉青"信号：逻辑对了但**肉眼看不见** —— 已解决

**症状**：按 F3 做出来的"整日清空 → 日期数字转玉青"，肉眼看日历**完全没有绿色**，像是没生效。

**排查**（不靠猜，靠像素）：
1. 先算数据：按 App 的 `dateOf` / `doneOf` 逻辑用真实数据复算，确认多天应当 allDone
2. 再写零依赖 PNG 解析脚本（`.tmp-data/png_green.py`）扫截图里的绿色像素
   → **438 个像素命中 `#7D9B76`**，集中在日历某行 → **逻辑其实生效了**
3. 结论：`TGColors.Jade = #7D9B76`（鼠尾草绿）在浅粉底上对比度只有 **2.7:1**，13sp 小字根本看不出来

**修复**：新增 `TGColors.JadeDeep = #3F6B4A`（对比度 **5.3:1**）专供日历使用。

> 教训：**"没生效"和"生效了但看不见"是两回事**。先取证据（像素扫描 / 数据复算）再改代码，
> 否则很容易把好的逻辑当坏的改掉。`png_green.py` 这个零依赖像素扫描以后验配色还能用。

**另注（F3 的表达边界）**：所有任务页的日历**只装未完成任务**（`active` 过滤掉了已完成），
所以那一页"整日清空"几乎不会出现；这个信号主要在**历史页日历**（数据源 = 已完成 ∪ 逾期展开）上体现。

## C-012 ⭐ 补丁"静默失败"：以为改了，其实一行没动 —— 已解决

**症状**：给「所有任务」页做完"阅览方式下拉菜单"补丁、也同步+编译成功了，
装机一看**顶栏还是原来的「日历」二态键**，代码像根本没改。

**根因**：那次补丁是放在**后台命令**里跑的，而我把后台日志用 `tail -12` 看 —— 只看到 gradle 的
`BUILD SUCCESSFUL`，**补丁脚本自己的输出（以及 assert 报错）被截掉了**。
实际上补丁在第一步就 `assert` 挂了（我拿 `import androidx.compose.material3.ExperimentalMaterial3Api`
当锚点，而这个文件的导入是**通配符** `import androidx.compose.material3.*`）→ 整个脚本 exit 1，
文件一个字没改。编译"成功"只是因为它编译的是**旧代码**。

**修复**：去掉多余的导入步骤（通配符已覆盖 DropdownMenu），重跑补丁并**在前台执行、完整看输出**。

**教训（写进流程）**：
1. **补丁脚本的输出必须完整看**，尤其在后台跑时；`tail -N` 会吃掉脚本自己的成功/失败信息
   → 现在统一在脚本末尾打印 `>>> SCRIPT_OK: ...` 标记，并在前台执行
2. **"编译成功"不等于"改动生效"** —— 改完 UI 必须**真机/截图确认新元素出现**，
   否则旧代码编译同样会 BUILD SUCCESSFUL
3. 锚点要选**这个文件里唯一**的文本；拿"导入语句"当锚点前先确认它的实际写法

## C-013 补丁插错函数：通用变量名当锚点 —— 已解决

**症状**：编译报 `Unresolved reference: searchOn / searchCompact / searchHeight / calScroll`（4 个都找不到）。

**根因**：我用 `val listState = rememberLazyListState()` 当锚点做 `replace(…, 1)`（只替换第一处），
但这个声明在文件里有**两处**（主页 `TaskListScreen` 第 138 行、所有任务页 `AllTasksScreen` 第 1229 行），
第一处是主页 → 整块"滚动压缩搜索框"的逻辑被插进了**主页**，而真正用到它的"所有任务页"里当然找不到。

**修复**：把整块剪切出来，用 `rindex()` 插到**最后**一处（= AllTasksScreen）。

**教训**：
- **别拿通用变量名当锚点**（`listState` / `searchOn` / `i` / `result`…）；要选唯一上下文
- 补丁里凡是用 `count=1` 的替换，都要先 `grep -c` 确认锚点在文件里只出现一次
- 出错后先看**报错行号落在哪个函数**，能立刻判断是不是插错地方了
