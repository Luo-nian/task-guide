# Debug 日志机制（每版本一份）

> 目的：boss 反复提到的同一个 bug，不用重新从头排查 —— 直接读日志里的「已试方案 / 结论 / 下一步」。
> 同时让反复出现的 bug 有据可查，优先级自然抬升。
> 建：2026-09-12（v5.15.20 流程需求）

## 为什么是「索引 + 详表」两层

boss 担心每次读日志吃 token。所以拆成两层，常态开销≈0：

| 层 | 文件 | 体积上限 | 何时读 |
| --- | --- | --- | --- |
| 索引 | `BUG-INDEX.md` | **≤ 2KB**（约 20 行） | 只在**触发词命中**时读 |
| 详表 | `debug-v<版本>.md` | ≤ 6KB / 份 | 只在**索引命中某条**时读那一份 |

## 读取规则（硬性）

1. **默认不读**。普通对话、新需求、无关问题 —— 不读索引，不读详表。
2. **触发词命中才读索引**。boss 话里出现下列任一情况：
   - 明确说「又 / 还是 / 上次那个 / 之前提过 / 没修好 / 一直都 / 反复」
   - 说「bug / 不行 / 有问题 / 报错 / 失效 / 没生效 / 白屏 / 闪」
   - 提到某个**已知症状关键词**（见索引的「症状关键词」列）
3. **命中索引某条 → 只读那一条对应的详表文件**，不批量读。
4. 每条详表控制在 ≤ 6KB；超了就拆「当前版本 / 历史版本」。

## 写入规则（硬性）

每个版本收尾时（commit 前）必须在该版本详表里补：

- **已解决**：一句话根因 + 修法落点（`文件:行号`）+ 指向需求文档
- **未解决 / 待验证**：现象 → 已试方案（逐个列出，含失败的那个）→ 当前结论 → 下一步 → **症状关键词**

同时在 `BUG-INDEX.md` 同步：
- 新出现且未解决 → 加一行
- 已解决 → **从「未解决」区删掉**，挪到「已解决归档」（只留一行，不写细节）

**索引只保留未解决的**，所以它会随时间自然变短，不会无限膨胀。

## 命名

- 详表：`debug-v5.15.20.md`（跟 `requirements/项目需求-v<版本>.md` 同号）
- 一个版本一份；跨版本没解决的 bug，在**最新版本**的详表里续写，索引里更新「首现版本 / 最新进展版本」

## 目录

```
debug/
├── README.md          ← 本文件（机制说明）
├── BUG-INDEX.md       ← 极简索引，唯一入口
├── debug-v5.15.19.md  ← 每版本详表
└── debug-v5.15.20.md
```
