## 一、手机端（6 项）

### M1 · 打卡键只显示一个提手旁「扌」
- **现象**：主页「每日任务」的习惯行，绿色打卡按钮里「打卡」被裁得只剩左半个字（提手旁）。
- **根因**：`PressIcon` 内部是 Material3 `IconButton`，它会强制 `.size(40.dp)` 固定尺寸。按钮左右 padding 各 16dp 先吃掉 32dp，只剩 8dp 给文字 → 两字被裁成半个字。
- **修法**：新增 `PressPill`（`Box` + `clickable`，保留按压缩放动画，尺寸跟内容走、无 40dp 约束），`HabitRow` 换用它。
- **验证**：`uiautomator` 取「打卡」节点 `bounds="[872,1779][960,1851]"`（88×72px，完整两字）；点击后正常弹「+9 积分」、总积分 1326 → 1335。

### M2 · 每日任务完成了就不要放在主页了
- **修法**：主页 `todo` 过滤掉 `type == HABIT && uuid in checkedHabits`（习惯不改 done、靠 habit_logs 记录，次日 lazy reset 后自动回到主页）。
- **验证**：打卡前主页有「每日任务 · 今日 (1)」+ 该行；打卡后整组消失。

### M3 · 从别的界面回到主页，如果有追踪任务 → 页面坐标默认放到最上面
- **修法**：显式持有 `rememberLazyListState()`；`LaunchedEffect(route)` 中回到 home 时 `if (tracking.isNotEmpty()) listState.scrollToItem(0)`（配合已有的 `showPinSection = true`）。
- **验证**：主页下滑到「次数任务」区 → 进「所有任务」→ 返回 → 页面自动回顶，「正在追踪 (3)」三张卡可见。

### M4 · 取消追踪键不该是 ✕，要是红色实心追踪键（追踪键镂空处填满），电脑端同样
- **修法**：新增专用图标 —— 安卓 `ic_track_fill.xml`、桌面 `targetFill`（`app3.js` ICONS）。用 `fillRule="evenOdd"` 在三重同心圆上挖一道细环槽，得到**实心靶心**，与原本的镂空靶心互为反相（追踪=镂空/天蓝，取消=实心/朱砂红）。
- **配色**：手机 `TGColors.Crimson`(#B85638)；桌面 `--crimson` 渐变 `#D4705A → #BC4A34`。
- **替换点（共 4 处）**：手机 `TaskRow`(追踪态) + `TrackTaskCard`；桌面行内三键 `data-act="stop"` + 详情页 `dva-b.stop`；另加挂件 `widget.html`。
- **验证**：
  - 手机：追踪卡右侧为红色实心靶心（截图确认），`content-desc="取消追踪"` 保留可用。
  - 桌面（CDP）：`.act[data-act="stop"] .b` → `linear-gradient(135deg, rgb(212,112,90), rgb(188,74,52))`、SVG `fill-rule=evenodd`、`fill=currentColor`、`stroke=none`；详情页 `.dva-b.stop` 同样；挂件 `.act.stop` 同样。

### M5 · 主页分类首项不该是「全部」，要是「今日」
- **修法**：`CategoryFilterRow` 加 `allLabel` 参数（默认「全部」）；主页传 `"今日"`，「所有任务」页保持「全部」（该页含未来任务）。
- **验证**：主页筛选条 = 今日 / 每日 / 目标 / 限时 / 次数。

### M6 · 「所有任务」里追踪中的任务应该置顶，而不是每日任务（今日打卡）置顶
- **修法**：`LazyColumn` 中把 `trackingF` 区块移到 `todayCheckedList` 区块之前。
- **验证**：顺序 = 正在追踪 (3) → 今日打卡 (5) → 待办 (7)。

## 五、本次踩到的新坑（已写进 memory）

1. **`PressIcon`(IconButton) 不能包文字按钮** —— Material3 `IconButton` 内部强制 `.size(40.dp)`，任何文字/胶囊按钮用它会撞死宽度。文字按钮一律用新加的 `PressPill`。
2. **Git Bash 里 `CARGO_TARGET_DIR` 不能用 POSIX 路径** —— 写成 `/d/taskbuild2/desktop-target` 时 Rust 收到的不是 Windows 路径，产物落到了意外位置 `D:\d\taskbuild2\desktop-target\`（我误把旧 exe 当新产物部署了一轮才发现）。**必须用 `D:/taskbuild2/desktop-target` 这种带盘符的写法**；部署前务必核对 exe 的 mtime/大小。
3. **gradle 启动器读的是 `JAVA_HOME` 环境变量** —— 只传 `-Dorg.gradle.java.home` 不够（那样在启动阶段就报 `jvm.cfg` 打不开）；要先 `export JAVA_HOME=...` 再跑 gradle。
