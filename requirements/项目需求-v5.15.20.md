## 设计说明：为什么不会吃 token

boss 的核心顾虑是「每次读日志增加上下文负担」。解法是**两层 + 触发式读取**：

| 层 | 体积上限 | 读取时机 |
| --- | --- | --- |
| `BUG-INDEX.md` | ≤ 2KB（约 20 行） | **仅当** boss 话里出现触发词（又/还是/上次那个/bug/不行/报错/失效…）或命中已知症状关键词 |
| `debug-v<版本>.md` | ≤ 6KB / 份 | **仅当** 索引命中某条，且只读那一份 |

- 普通对话、新需求、无关问题 → **两份都不读**，开销为 0
- 索引只保留未解决的，修好即删 → 随时间自然变短
- 详表单版本封顶 6KB，超了就拆「当前版本 / 历史版本」只读当前

## 附：这套机制的写入纪律（每版本收尾必做）

1. 详表补「已解决根因（一句话 + 文件:行号）」+「未解决项（现象/已试/结论/下一步/症状关键词）」
2. 索引同步：新增未解决 → 加行；已解决 → 从「未解决」区删掉，挪归档
3. commit 时 debug 目录一并提交
