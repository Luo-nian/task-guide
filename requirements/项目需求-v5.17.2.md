# 项目需求 v5.17.2（2026-09-19 晚）

> boss：「为什么现在在不断断联重连 … 一直断联重连就一直都很卡！给我修！」

## R1 · 修复「WS 每 5 秒断联重连 → 界面卡顿」

### 根因（实验证实，非推测）
WS 握手 token 是**标准 base64**（含 `+` `/` `=`），却**原样拼进 URL query**：
```
ws://10.103.157.105:8899/ws?token=BtOcIg/B3C6B0w0dPDr9ZH3mrxQEdiq5o+Y6q+lO2iY=
```
`+` 被服务端按 `x-www-form-urlencoded` 解成**空格** → `wsTokenOk` 校验失败
→ 101 升级成功后**立刻发关闭帧 1008 unauthorized** → 桌面端 `read()` 立刻报错
→ 睡 5 秒重连 → **死循环**。
且**每次重连都触发一次 full_sync 全量拉取**（238 行写库 + 通知前端重渲染）
→ 这才是"一直断联重连就很卡"的真正来源（断一下本身不卡，反复全量才卡）。

### 实验证据（Python 裸 WS 握手，三种传法对比）
| 传法 | 结果 |
| --- | --- |
| 原样（含 `+ / =`） | 101 → 收到关闭帧 **1008 unauthorized** ❌ |
| **百分号编码** | **连接保持 ✅** |
| URL-safe 替换 | 也失败（服务端只认标准 base64） |

### 修法（4 处）
1. `sync.rs` 新增 `url_encode()`（只保留 `A-Za-z0-9-_.~`），WS URL 用编码后的 token
2. `sync.rs` **重连触发的 full_sync 加 20s 节流**（原来每次重连都全量拉 → 抖动即风暴）
3. `Auth.kt` `wsTokenOk` 解码容错：标准 / URL-safe / 把空格还原成 `+` 都认
4. 两端重新编译 + 装机

### 实测对比
| | 修复前 | 修复后 |
| --- | --- | --- |
| 50 秒内 WS 重连次数 | ~10 次 | **1 次** |
| 100 秒观察窗口 | — | **0 重连 / 0 失败** |
| 长时静默 | — | 最后一条日志后 **85 秒零日志**（连接稳定） |
| 全量同步 | 每 5 秒一次 | 连接建立时一次，238/238 成功 |

## 经验（已写进项目 MEMORY.md）
> ⭐ **标准 base64 放进 URL query 必须百分号编码**（`+` → 空格）；
> ⭐ **重连触发的全量同步必须加节流**，否则网络抖动 = 反复全量 = 卡死。
