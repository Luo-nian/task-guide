## 3 · 技术要点

- `/api/task_changes` 走既有 `guard("GET")` + `respondSecure` 链（ChaCha20 双向认证），新增 `ChangeLogDto`（who/action/detail/at）瘦身暴露
- 桌面 `task_changes` 命令用 `secure_get`（免系统代理 lan_client + 签名 + 解密），失败返回 `{error}` 形状，JS 据此隐藏整段
- `delete_step` 桌面本地软删后 `push_change` 同步手机；反向（手机删→桌面）`apply_change ("delete","step")` 已存在
- B-008 采用 dark 作用域覆盖（`!important` 局部），不动白天样式，规避 110 处全量重构风险

## 3.1 · 真机验证中发现并当场修复（v5.29.0 收口内）

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 桌面拉时间线 401 bad_sig | `secure_get` 把 query 串进签名 path；手机端 `guard` 用 `request.path()`（**不含 query**）验签 | `secure_get` 按 `?` 拆分：签名/响应验签只用 path，请求带完整 query |
| 未配对时「动态」区误显示「还没有动态」 | rust 把错误吞成 `[]`，JS 无法区分 | 失败返回 `{error}`，JS 隐藏整段 |
| 夜间主题详情抽屉仍暖白 | `.main-pane:695` 等硬编码渐变未被覆盖 | 二轮补 `.main-pane`/`#catCardTracking`/`.style-tab`/`#_softTip` dark 覆盖 |
