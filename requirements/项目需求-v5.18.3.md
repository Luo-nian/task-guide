# 项目需求 v5.18.3（2026-09-20 凌晨）

> boss：「为什么每日任务会出现逾期情况 不是零点刷新吗」

---

## 共同根因（一处数据设计问题，引出两个 bug）

每日型任务（`category=daily` / `type=habit|repeat` / `repeat_rule=daily`）的 `due_at`
存的是**「每天几点提醒」**（例如 09:00），而且**创建后从不推进** ——
全仓确认无任何"滚动到明天"的逻辑。

于是**所有"拿 due_at 和当前时间比大小"的判定都会错**：

- 零点折算（`normalizeDailyReset`）只把 `trackStatus/done/doneAt` 折回待办，**不动 due_at**
- 结果：第二天一过零点，due_at（昨天 09:00）就已经是过去时

boss 数据实证：`健身 / type=habit / category=daily / repeat_rule=daily / due_at=09-18 09:00`

---

## R1 · 桌面端把每日任务标成「逾期」（已修）

**病灶**：`app3.js` 的 `isOverdue(t)` = 「未完成 且 已过 due_at/deadline」，**完全不区分任务类型**。
每日任务过了当天提醒时刻 → 显示「已逾期」；第二天零点折算回待办后 → **「逾期 1 天」**。

**修法**：新增 `isDailyKind(t)`（`category==='daily' || type==='habit' || repeat_rule==='daily'`），
`isOverdue()` 与 `overdueText()` 对每日型一律返回"不逾期"。
每日任务照常显示提醒时间胶囊（如 `09:00`），只是不再出现"逾期"字样。

**验证（node 抽函数单测，6 用例全过）**：
| 用例 | 期望 | 结果 |
| --- | --- | --- |
| 每日任务（健身，due_at 已过） | 不逾期 | ✅ |
| 只给 type=habit | 不逾期 | ✅ |
| 每日任务未到点 | 不逾期 | ✅ |
| 每日任务已完成 | 不逾期 | ✅ |
| **限时任务真逾期（deadline 已过）** | **逾期** | ✅ |
| **普通任务真逾期（due_at 已过）** | **逾期** | ✅ |

---

## R2 · 手机端每次启动都把每日任务当「已过期未完成」立即提醒（已修）

**病灶**：`ReminderScheduler.rescheduleAll()` 里

```kotlin
var due = t.dueAt                      // 永远是过去的时刻
if (due > now) schedule(...)
else NotificationHelper.showReminder(...)   // ← 每日任务天天走进这里
```

注释写的是「已过期未完成 → 立即提醒（未完成警告）」，但每日任务的 due_at 天然在过去
→ **每次冷启动 / 开机都会给每日任务弹一次提醒**，等于天天把它当逾期。

**修法**：
1. 新增 `isDailyKindForReminder(t)` 与 `nextDailyOccurrence(dueAt, now)` ——
   把 due_at 的「时:分」折到**今天那个时刻**（今天已过则明天那个时刻）再排闹钟
2. 每日型任务**不走**「已过期立即提醒」分支（它们没有"逾期"这回事）

## 遗留（记录，未改）

更彻底的做法是**每天零点把每日任务的 due_at 推进一天**，这样所有消费者都不用各自折算。
但那是"改数据 + 会同步到另一端"的改动，风险与收益都要再评估 ——
本次采用两端各自折算的方式，**不动数据**。
若后续发现第三处按绝对时间比较的地方，就应当考虑做数据侧的滚动。
