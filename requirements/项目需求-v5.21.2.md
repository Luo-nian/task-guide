## R2 · 桌面端「未完成弹窗」时间可自定义

boss 原话：「**这个时间也让用户自己设置 因为有人早睡早起**」（原 UI 写死「22:00」）。

| 层 | 改动 |
| --- | --- |
| `index.html` | 设置行改为「未完成弹窗」+ 开关 + **时:分 两个小输入框**（复用「每日任务刷新时间」那套 `.tbox`）；夜间弹窗副标题去掉写死的「22:00」 |
| `app3.js` | 新增 setting `night_notify_time`（'HH:MM'，默认 '22:00'）；`_setNightTime/_readNightTime/_commitNightTime/bindNightTime`；弹窗副标题按设置渲染；进同步 payload |
| `lib.rs` | 写死的 `Local::now().hour() < 22` → 读 `night_notify_time` 判定；新增 `parse_hhmm()`（容忍 `H:M` 与纯 `HH`，越界回落默认） |

### 验证（**决定性 A/B**，不是"看代码说应该行"）
先造一条「今天的限时任务」让判定链能走到底，再只改触发时刻：

| 触发时刻 | `check_night_notify` 返回 |
| --- | --- |
| `00:01`（此刻已过） | ✅ `pending: true, count: 1` |
| `23:59`（此刻未到） | ✅ `pending: false` |

弹窗副标题实测 `00:01 了，还有任务没完成` ✅（跟着设置走）。
设置页实测：新行存在、时间框回填 `22:00` ✅。
测试后已删临时任务、把设置还原成 `22:00`、清掉 `last_night_notify`（不影响今晚真正的提醒）。

⚠️ 第一次 A/B 得到 `pending:false` 差点误判 —— 原因是当时没有未完成任务，
判定链在**最后一道**（任务集合为空）就返回了 false，**时间判断根本没被暴露**。
→ 教训：**测"条件 A 是否生效"时，必须保证 A 之后的条件全部成立**，否则测不出东西。

## R3 · 手机端 App 图标与电脑端统一

boss：「**手机端的 app 图标和电脑端没有统一 都用电脑端的**」。

- 电脑端图标来源：`desktop/scripts/gen_icons.py`（米底渐变 + 三条深褐 #3A2E1A 圆头线 + 金色 #C9A227 对勾）。
- 手机端原来是**完全不同的**指南针向量（`ic_launcher_foreground.xml`）+ 深蓝灰渐变底。
- 改法（minSdk=26 → 只需自适应图标，无需多密度位图）：
  - `drawable/ic_launcher_background.xml` → `#FCF7EB → #F1E6C8` 自上而下微渐变（与电脑端同）
  - `drawable/ic_launcher_foreground.xml` → 用**同一套几何**：把 1024 画布上的三条线与对勾按「图形宽 62dp」等比映射进 108 viewport，收在 66dp 安全圆内（缩放系数 0.09051；线宽 4.89、对勾 7.6）
  - `mipmap-anydpi-v26/ic_launcher.xml` / `ic_launcher_round.xml` 原本就指向这两个 drawable，不需要改

### 验证
1. 先按同一套数字用 Pillow 渲染预览（含圆形/方形遮罩 + 48/72/144px 缩略）→ `src/docs/assets/手机图标-预览.png`，肉眼确认 48px 下仍认得出。
2. 装机后用系统「应用信息」页（`am start -a android.settings.APPLICATION_DETAILS_SETTINGS`）验证系统渲染：
   实测图标为「米底圆角 + 三条深褐线 + 金对勾」，与电脑端一致；App 名显示 `next任务` ✅
