### 六条真根因

**自动扫描（S1–S3）**
1. **R1【主因】** `autoScanAndReconnect` 只在【启动后 3s】+【打开设置页】各跑有限轮就**永久停手** →
   「启动时手机还没上网」「中途断网恢复」「手机 WiFi 重连」全部场景**一次扫描机会都没有**
2. **R2** Rust 侧 mDNS 重发现窗口只有 4s、失败后要等 8s 才有下一次 → 手机刚连 WiFi 时几乎必然扫空
3. **R3** 前端文案写「点击下方"扫描设备"重连」→ 误导 boss 以为必须手点

**手机端连接状态（S5–S7）**
4. **R4** 手机端**压根没有「已连接」UI** —— 只有「已配对：XXX」，而那是**历史记录**，
   电脑断开后依旧显示"已配对"，用户无法判断实际状态
5. **R5** **自动重连后不补发配对通知** —— `/api/pair` 只在手动配对那一刻发一次；
   且自动重连路径**少发 `deviceName`**（手机端 `ApiRoutes` 读的正是 `deviceName`）
6. **R6** 手机端**无任何地方暴露 WS 连接状态给 UI**

### 修法要点

**自动扫描**：前端加**常驻看门狗**（每 5s 检查「已配对 && 未连接」→ 持续自动扫描，连上即停）；
Rust 侧改**自适应**（扫描窗口 4s→8s→12s；轮询 5s→2s；ping 超时 3s→1.5s）；文案全改「正在自动扫描重连…」

**连接状态**：手机端新增 `LinkState`（`MutableStateFlow<Boolean>`，**WS 连接真值**，非缓存设置）→
WS 连上/断开即时反映；设置页配对卡按 `connected` 优先渲染三态；主页顶栏加状态小圆点。
桌面端 `ws_loop` **每次 WS 连上都补发** `/api/pair`（含 `deviceName`）。

**预估发现耗时**：旧 = 永不发现（除手动点）；新 = **≤ 10s**
