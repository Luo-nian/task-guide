## 三、第四轮的结论：**体验层面暴露的问题比 bug 更伤**

### A. 四个结构性短板（多份报告交叉命中）
| 短板 | 证据 | 谁能感觉到 |
| --- | --- | --- |
| ⭐⭐ **协作根本不存在** | 任务表**无负责人/指派字段**；同步协议自述"单人使用简化版"；双端 LWW 静默互相覆盖、**无活动流**；提醒只响"作为服务器的那台手机" | 丈夫、医生同事、前端同事 |
| ⭐⭐ **远程照护不可行** | 看不到"他今天吃药了没"，**没有回执/确认机制**；想看只能靠配对（且一对一） | 独居老人的女儿 |
| ⭐⭐ **隐私在专业场景是死线** | 锁屏通知 `VISIBILITY_PUBLIC` **明示任务名**（医疗场景=患者信息裸奔）；DB 明文、无加密 | ICU 医生 |
| ⭐ **信息架构过载** | 两个悬浮钮、一排无字图标、中央键语义随上下文漂移、隐式左右滑翻页 | 室友（"先做减法"） |

### B. 长期与首次使用的体验断层
- **第 3 个月**：任务变"僵尸"、只真正用 2~3 个功能（二八）、连击断了归零**无补卡**、两月数据**无搜索**
- **首次使用（无使用记忆）**：**没有新手引导**，"次数任务/时间周期/提前提醒"这些功能**自己发现不了**；前 3 分钟没有钩子
- **等级体系**：设计规范里 **Lv.1–4 零光效、Lv.5 才"活"** → 用了两个多月的人**一枚会动的徽章都没见过**（初三男生报告的核心）
- **键盘效率**：全仓仅 2 处 `keydown`，列表行**不可聚焦**、整页右键被 `preventDefault` 吞、无批量操作（前端同事）

### C. ⭐ 商业定律应用（各报告共 68 条，这里提炼最关键的 8 条）
| 定律 | 在这个 App 上的体现 | 对应建议 |
| --- | --- | --- |
| **木桶定律** | 长板是"暖色审美 + 桌宠 + 零账号"，短板是**协作 / 隐私 / 数据可迁移** —— 短板决定它能不能进"多人/专业"场景 | 先补短板，再谈加功能 |
| **马太效应** | 任务类 App 赢家通吃；早期没有"被推荐"的钩子就会被大厂挤压 | 做一个**值得被说出口**的卖点（真诚推荐话术已被多份报告给出） |
| **幸存者偏差** | 我们只测了"愿意填报告的人"；大量用户**装了 3 天就卸载**，他们的意见没人听见 | 增加"第 1 天/第 3 天流失"专项测试 |
| **峰终定律** | 用户记得的是**最高峰**与**结尾**：完成庆祝是峰（不错），但"月末回顾/换机"是终值（很糟） | 把"终值"做厚：月报、导入、成就回顾 |
| **Kano 模型** | "提醒可靠 / 数据不丢 / 隐私"是**必备属性**（没有就怒），"桌宠/等级"才是魅力属性 | 必备属性优先投入，别在魅力属性上加戏 |
| **损失厌恶** | 连击断裂归零、换机全丢、扣分掉级 —— 全部是"损失"刺激，而**没有一条"找回"的路** | 加补卡、导入、恢复回执 |
| **福格行为模型 B=MAP** | 动机够（想记事务），但**能力门槛高**（无引导、无快录入口）、提示弱（挂件"+ "无效） | 降门槛：快捷录入、挂件修复、首启引导 |
| **二八定律** | 90% 用户只用 2~3 个功能（提醒 / 打卡 / 今日列表），其余功能是"开发成本" | 首页只留今天；其余收进次级入口 |
