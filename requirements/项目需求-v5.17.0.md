## 已实现

### R1 · 配对改版：取消配对码，改双向确认
- 手机端 `server/Auth.kt` 新增 `PairingState`（配对模式 / 限流 / 单 pending / SAS / TTL / IP 绑定）
- 手机端 `ui/SettingsScreen.kt`：进入设置页自动开启配对模式；收到申请弹**确认框**
- 桌面端新增 `pair_request` + `pair_poll` 两个命令（替换 `pair_with_code`）
- 桌面端 `ui/index.html` + `app3.js`：扫描结果点「配对」→ 立即发申请 → 显示同一验证码 → 轮询

### R2 · 「确认之前的锁」四道门
配对模式门控 / 同 IP 3 次每分 / 单 pending / SAS 双屏核对
+ sessionId 128 位 + TTL 120s + 仅发起方 IP 可轮询 + 密钥一次性交付

### R3 · 传输加密与请求签名
- 新增 `desktop/src/tbcrypto.rs` 与 `mobile/.../server/Crypto.kt`（**同一套算法的镜像实现**）
- ChaCha20 + HMAC-SHA256，两把派生密钥，encrypt-then-MAC
- 请求签名四件套 + body 加密；**响应也签名（双向认证）**；WS 帧同样加密
- 依赖只加 `sha2` + `base64`（都在离线 registry 里），**没有引入 AES/ring**

### R4 · 两处交叉验证
Rust ChaCha20 对 RFC 8439 标准向量一致（rustc 直接跑真实代码）；
两端各带 KAT 自检 + 配对时互校

### R5 · 修三处漏改
`/api/settings/upsert` 未签名 → 401 静默失败；自动重连反 POST 已删接口 → 404；
`disconnect_server` 里 base 永远为空 → "通知手机解除配对"从未生效

### R6 · 上线行动清单（新增 docs/上线行动清单-v5.17.md）
核实三条硬门槛：Google Play 个人新号需 12 测试员 ×14 天；微信/支付宝 App 支付仅接受公司主体；
苹果中国区需 ICP 备案号。结论：3 天上线主流商店不可能，"官网直发"1–2 天可做到

### R7 · 文案精简（"后半句多余"清理，6 处）
1. `已配对 · 实时连接中：url` → `已配对：url`（连接状态右下角胶囊已有）
2. `已配对（缓存）· 当前未连接 — 正在自动扫描重连…` → `已配对：url`
3. 个人信息卡 `在 设置-连接与外观 里扫描或输入手机地址` → `扫描设备，或直接输入手机地址`
4. 扫描按钮旁 `扫描手机端「任务栏」服务` → 删除（按钮已自明）
5. 手机端 `已配对：X — 电脑端未连接，等待自动重连…` → `已配对：X`
6. 手机端配对指引第③条 → 删除（确认框里已逐字说过）
7. 手机端 `已配对：X · 实时同步中` → `已配对：X`
