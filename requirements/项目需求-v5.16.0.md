## 二、安全审计（P0 已完成）

### 发现的漏洞

| ID | 等级 | 问题 | 位置 |
| --- | --- | --- | --- |
| SEC-1 | 🔴 P0 | 手机端 API **完全无鉴权**，且监听 `0.0.0.0:8899` —— 同一 WiFi 下任何人可读/写/删数据 | `SyncService.kt:90` + `ApiRoutes.kt` |
| SEC-2 | 🔴 P0 | 配对机制形同虚设：`/api/pair` 不校验任何凭证（配对码从未被使用） | `ApiRoutes.kt:60`（旧） |
| SEC-3 | 🟠 P1 | 明文传输（http/ws，无 TLS），局域网可嗅探 | `sync.rs:506` |
| SEC-4 | 🟠 P1 | 数据明文存储（普通 SQLite，无加密） | 双端 |

桌面端良好实践：单实例锁只绑 `127.0.0.1:53911`，不对外暴露 ✓

### 加固实现（已完成，待编译验证）

**手机端**：
- 新增 `server/Auth.kt`：
  - `PairCode` —— 一次性 6 位配对码（**5 分钟有效 / 最多试 5 次 / 用过即废**）
  - `AuthState` —— 32 字节随机长期密钥（存 settings，不参与同步避免自锁）
  - `requireAuth()` —— 路由级鉴权（`X-TB-Token`，**常量时间比较**）
  - `wsTokenOk()` —— WS 握手鉴权
- `ApiRoutes.kt`：除 `/api/ping` 与 `POST /api/pair` 外，**全部接口要求鉴权**
- `SettingsScreen.kt`：配对区显示 6 位码 + 倒计时 + 「换一个」；解除配对时**同时作废密钥**

**桌面端**：
- `sync.rs`：新增 `AUTH_TOKEN` 全局；`full_sync` / `push_full` / `push_change` 全部带 `X-TB-Token`；
  WS 握手带 `?token=`；**删除"每次重连补发 /api/pair"的可重放逻辑**
- `lib.rs`：新增 `pair_with_code` 命令（提交配对码换取密钥）；
  `pairing.json` 增加 `token` 字段并在启动时恢复
- `index.html` + `app3.js`：配对区新增「配对码」输入框；扫描结果改为"填入地址 → 引导输码"，**不再一键配对**
