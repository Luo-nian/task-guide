## 三、v5.25.0：本轮修的 2 项

### 1. ⭐⭐ 导入备份 + 授权码随备份恢复（欠了四轮的账）

**欠账来源**：每一轮体验测试都被点名 —— 「导出只能出去、拿不回来」「换手机 = 数据全丢」
「买断授权码不跟着备份走」「等级和连续天数一起归零，App 还认不出你是老用户」。

**改动：**

| 文件 | 内容 |
| --- | --- |
| `data/repo/TaskRepository.kt` | 新增 `importFullSyncPayload(payload)` —— **合并语义**：按 uuid upsert、同 uuid 以 `updated_at` 新者胜；**不写 `auth_secret`**（本机配对密钥不能被别人的备份顶掉）；`total_points` **只增不减**（避免「恢复备份反而掉级」）；习惯打卡按 (task_uuid, check_date) 去重 |
| `billing/License.kt` | 新增 `rawCode(ctx)` —— 暴露原始授权码，供导出时带上 |
| `ui/SettingsScreen.kt` | ① 导出改为**包装格式**：顶层 `{ format, version, exported_at, license_code, payload }`；② 新增 `readBackup()`（兼容新包装格式与旧的裸 payload）；③ 「数据备份」卡片加「**导入 JSON 备份**」按钮 + 系统文件选择器 + 导入前确认对话框（显示条数、是否带授权码）；④ 导入后**自动重排提醒** |

**为什么授权码不直接加进 `FullSyncPayload`**：那是同步载荷，加了会把授权码**发给配对的桌面端**
（v5.22.5 刚把 `auth_secret` 从导出里剔掉，不能又漏一个）。所以走包装格式的旁路字段。

**真机验证：**

| 验什么 | 结果 |
| --- | --- |
| 导出文件顶层结构 | ✅ `['format','version','exported_at','license_code','payload']`，`format=taskguide-backup` |
| 授权码是否随备份 | ✅ `license_code=有` |
| 是否仍泄漏配对密钥 | ✅ `auth_secret: False` |
| 备份内容 | ✅ `tasks=1 steps=0 habit_logs=80 settings=12` |
| 导入入口在设置页 | ✅ 「导入 JSON 备份」按钮已出现 |
| **导入全链路（选文件 → 确认 → 落库）** | 🚧 **未走通** —— 系统文件选择器点选时弹出了系统「打开方式」面板（非我方对话框），本轮未能在真机上完成端到端验证，**代码与编译已通过，标待验证** |

### 2. ⭐⭐ 锁屏隐私档（专业场景死线）

**来源**：第四轮「ICU 医生」点名 —— 锁屏通知是 `VISIBILITY_PUBLIC`，**任务名明晃晃显示在锁屏上**，
在病房/办公室等于把工作内容亮给所有人。

**改动：**
- `notify/NotificationHelper.kt`：按 `lock_hide_content`（默认 **true**）决定
  ① 标题 → `你有任务到点了`（否则为任务名）② 正文 → `解锁查看详情`
  ③ `setVisibility(VISIBILITY_SECRET)`（否则 `PUBLIC`）
- `ui/SettingsScreen.kt`：「提醒方式（默认）」卡片加开关「**锁屏隐藏任务名**」+ 说明文案

**真机验证：** ✅ 设置页出现「锁屏隐藏任务名」；✅ 通知链路正常（演示通知 `vis=PRIVATE` 正常弹出）；
⚠️ 真实提醒的隐藏文案未抓到 —— 手上唯一可见任务「健身」是 `done` 状态，`fireNow` 会直接跳过，**标待验证**。
（广播契约已确认可用：`am broadcast -n com.taskbar.app/.notify.ReminderAlarmReceiver --es task_uuid <uuid> --es strength notify`）

### 第四轮挖出的结构性短板（不是 bug，是天花板）

1. ⭐⭐ **协作根本不存在**：任务表没有「谁负责」字段、双端 LWW 静默覆盖、无活动流、**提醒只响当服务器那台**
2. ⭐⭐ **远程照护不可行**：子女装 App 想盯父母吃药，**看不到「他今天吃了没」**（无回执）
3. ⭐⭐ **隐私是专业场景死线**：锁屏通知公开可见、DB 明文 → 本轮已修锁屏部分
4. ⭐ **信息架构过载**：两个悬浮钮、一整排无字图标、中央键语义随页面漂移、隐式左右滑
5. **长期（第 3 个月）**：任务变僵尸、真正在用的只有 2~3 个功能、连击断裂无补卡、几十条数据无搜索
6. **首次（无使用记忆）**：**没有任何新手引导**，次数任务/周期/提前提醒这些好功能用户自己发现不了
7. **等级有洞**：设计规范里 Lv.1–4 **零光效** → 用两个月的人一枚「会动」的徽章都没见过
8. **键盘流缺失**（桌面端）：仅 2 处 keydown、行不可聚焦、右键被吞、无批量

### 补跑那份（退休教师·无使用记忆）的独有发现

- **「放弃点」在空状态**：空状态只写「点右下角加号」，但底栏只有两个**无字图标**，
  第一次用的人前 3 分钟连入口都找不到（`MainActivity.kt:230-232`、`Screens.kt:2143`）
- **系统字号调到最大必挤爆**：App 内字号写死无设置、说明文字 11sp、胶囊键 `maxLines=1` 不换行
  （`UiFoundation.kt:111/540/554/568/584`），且已有「打卡」被裁成「扌」的先例
- **「每天两次吃药」自建不了**：每日任务只有一个时刻编辑器（要建两条）；「提醒」默认「不提醒」且标「（可选）」，
  老人跳过就永不响；提前提醒也不能设两个时间（`TaskDetailScreen.kt:653-659/703/706/726`）
- **误触无退路**：长按 320ms 进编辑（老人停指即误入）；多选界面的「取消」实为删除

## 五、商业定律提炼（各报告共 68 条 → 8 条）

| 定律 | 在这个 App 上的体现 |
| --- | --- |
| **木桶定律** | 长板 = 审美 + 桌宠 + 零账号；短板 = **协作 / 隐私 / 数据可迁移** → 短板决定它进不了家庭、团队、专业场景 |
| **马太效应** | 工具类赢家通吃，而现在缺一个「能被说出口」的推荐理由 |
| **幸存者偏差** | 我们只听到愿意填报告的人；装了 3 天就卸载的人一句话都没留下 |
| **峰终定律** | 记住「最高峰」与「结尾」——完成庆祝（峰）不错，但**换机 / 月末（终值）最糟** |
| **Kano 模型** | 提醒可靠、数据不丢、隐私 = **必备属性**（缺了直接愤怒）；桌宠 / 等级只是加分项 |
| **损失厌恶** | 全是「扣分、归零、丢失」，**却没有一条「找回」的路**（无补卡、无导入、无回执） |
| **福格 B=MAP** | 动机够（想记事），但**能力门槛高**（无引导、无快捷录入）、**提示弱**（挂件「+」是死的） |
| **二八定律** | 90% 的人只用 2~3 个功能 → 首页只留「今天」就够，其余是开发成本 |
